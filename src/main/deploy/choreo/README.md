# Choreo Trajectories

## Overview

This directory contains trajectory files generated by Choreo (https://sleipnirgroup.github.io/Choreo/), a trajectory optimization tool for FRC robots.

## File Types

Each Choreo path consists of two files:

### `.chor` Files (Source)
Editable project files opened in the Choreo application.

**Contents:**
- Waypoint positions and headings
- Constraint definitions (stop points, keep-in-rectangle, max velocity, etc.)
- Robot configuration (bumper size, wheel specs, motor specs)
- User-editable parameters

**Example:** `ExampleAuton.chor`

### `.traj` Files (Compiled)
JSON files containing optimized trajectory samples, generated by Choreo from `.chor` files.

**Contents:**
- Discrete time-stamped samples (typically 50 Hz = 0.02s intervals)
- For each sample: `t`, `x`, `y`, `heading`, `vx`, `vy`, `omega`, `ax`, `ay`, `alpha`
- Module-specific forces: `fx`, `fy` arrays for each swerve module

**Example:** `ExampleAuton.traj`

## Trajectory Structure

### Waypoints
Fixed points the robot must pass through:
```json
"waypoints": [
  {
    "x": {"exp": "7.8466 m", "val": 7.846601},
    "y": {"exp": "0.4194 m", "val": 0.419445},
    "heading": {"exp": "0 deg", "val": 0.0},
    "intervals": 22,
    "split": false,
    "fixTranslation": true,
    "fixHeading": true
  }
]
```

**Key Properties:**
- `split: true` - Creates a stop point (separates trajectory into segments)
- `fixTranslation` - Locks waypoint position
- `fixHeading` - Locks waypoint rotation
- `intervals` - Number of samples between waypoints (affects smoothness)

### Constraints
Rules enforced during trajectory generation:

```json
"constraints": [
  {"from": "first", "to": null, "data": {"type": "StopPoint"}},
  {"from": "last", "to": null, "data": {"type": "StopPoint"}},
  {"from": "first", "to": "last", "data": {
    "type": "KeepInRectangle",
    "props": {"x": 0.0, "y": 0.0, "w": 17.548, "h": 8.052}
  }}
]
```

**Common Constraint Types:**
- `StopPoint` - Robot velocity = 0 at this waypoint
- `KeepInRectangle` - Robot must stay within field boundaries
- `MaxVelocity` - Speed limit for segment
- `MaxAngularVelocity` - Rotation rate limit

### Samples
Discrete trajectory points for robot to follow:

```json
"samples": [
  {
    "t": 0.0,
    "x": 7.8466, "y": 0.41944, "heading": 0.0,
    "vx": 0.0, "vy": 0.0, "omega": 0.0,
    "ax": -8.84993, "ay": 0.25141, "alpha": 0.14644,
    "fx": [-150.51, -150.56, -150.56, -150.51],
    "fy": [5.08, 3.43, 3.46, 5.14]
  }
]
```

**Field Meanings:**
- `t` - Time (seconds)
- `x`, `y`, `heading` - Pose
- `vx`, `vy`, `omega` - Velocity (m/s, m/s, rad/s)
- `ax`, `ay`, `alpha` - Acceleration (m/s², m/s², rad/s²)
- `fx`, `fy` - Forces for [FL, FR, BL, BR] modules (N)

## Trajectory Segments

When a trajectory has `split: true` waypoints, it's divided into segments:

```
ExampleAuton (7 waypoints, 3 splits):
  Segment 0: Waypoint 0 → Waypoint 2 (SPLIT)
  Segment 1: Waypoint 2 → Waypoint 3 (SPLIT)
  Segment 2: Waypoint 3 → Waypoint 4 (SPLIT)
  Segment 3: Waypoint 4 → Waypoint 5 (SPLIT)
  Segment 4: Waypoint 5 → Waypoint 6
```

Each segment can be accessed separately in code:
```java
AutoTrajectory segment0 = routine.trajectory("ExampleAuton", 0);
AutoTrajectory segment1 = routine.trajectory("ExampleAuton", 1);
```

**Use Case:** Insert commands between segments (e.g., intake game piece, score, etc.)

## Loading in Robot Code

### ChoreoLib Integration

```java
// AutonSubsystem.java
private final AutoFactory autoFactory = new AutoFactory(
  swerveSubsystem::getPose,
  swerveSubsystem::resetPose,
  swerveSubsystem::followPath,  // Consumes SwerveSample
  false,
  swerveSubsystem
);

// Load trajectory by name (without extension)
AutoRoutine routine = autoFactory.newRoutine("ExampleAuton");
AutoTrajectory trajectory = routine.trajectory("ExampleAuton");

// Reset odometry and follow
routine.active().onTrue(
  trajectory.resetOdometry().andThen(trajectory.cmd())
);
```

### Path Following

```java
// SwerveSubsystem.java
public void followPath(SwerveSample sample) {
  var pose = getPose();
  ChassisSpeeds speeds = new ChassisSpeeds(
    sample.vx + m_pathXController.calculate(pose.getX(), sample.x),
    sample.vy + m_pathYController.calculate(pose.getY(), sample.y),
    sample.omega + m_pathThetaController.calculate(pose.getRotation().getRadians(), sample.heading)
  );
  setControl(m_pathApplyFieldSpeeds.withSpeeds(speeds));
}
```

Choreo provides feedforward (`sample.vx`, `sample.omega`) + PID provides feedback correction.

## Coordinate System

- **Origin:** Blue alliance lower-left corner
- **Units:** Meters
- **Angles:** Radians (counter-clockwise positive)
- **Field Size:** 17.548m × 8.052m (constraint bounds)

## Creating New Trajectories

1. Open Choreo application
2. Configure robot parameters (match `AutonConstants.java`)
3. Place waypoints on field
4. Add constraints (stop points, velocity limits, boundaries)
5. Generate trajectory
6. Export to `deploy/choreo/`
7. Load by name in `AutonSubsystem.java`

## Differences from PathPlanner

Choreo focuses on **trajectory optimization** with physics-based constraints.

PathPlanner focuses on **real-time pathfinding** and path following.

2025 code uses:
- **Choreo:** Pre-planned test paths (not used in competition)
- **PathPlanner:** Dynamic navigation to game elements (AssistCommand)
- **Hybrid:** PathPlanner for global planning + Choreo concepts for path quality
